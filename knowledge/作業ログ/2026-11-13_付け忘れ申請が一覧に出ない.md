# 打刻の付け忘れ申請が管理者の一覧に出ない（2026-11-13）

**きっかけ**: VLL しの・星狼 透から「修正申請が来ているらしいが見えない」（高野経由 2026-11-13）／**ブランチ**: `fix/correction-list-missing-attendance`（`feature/multi-clock-in` から。main 未マージ）

## 原因

修正申請一覧・ホームの「未処理の修正申請」・件数バッジが `attendance: { organizationId }` だけで絞っていた。
付け忘れ申請（7/24 `47d05df` で追加）は勤怠を持たない（`attendanceId = null`）ので、この条件で全部外れる。
詳細ページと承認処理は付け忘れに対応済みだった（URL を知っていれば承認できた）。権限の問題ではない（しの = VLL の OWNER、透 = データローの ADMIN）。

本番の未処理（2026-11-13 本番DB 読み取り）: VLL 2件（八重桜 11/6・11/7 分。2件とも付け忘れ）／データロー 9件（うち付け忘れ8件。9/18〜10/13 申請、10/5 の会議・TikTok 研修分が中心）。見えていたのは 9/2 ミツルの1件だけ。

## 変えたこと

- `lib/business/correction-request-scope.ts`: 「勤怠の組織」または「付け忘れ申請の店舗の組織」で絞る。担当店舗スコープは両方に効かせる
- 一覧・ホーム・件数バッジをこれに寄せた。ホームは店舗スコープも新たに効かせ、店舗・営業日を申請自身からも出す（`req.attendance.store` を直接読んでいたので、付け忘れが出ると落ちるところだった）
- 詳細ページ: 付け忘れ申請も店舗の組織を確かめる（別組織の OWNER が ID 指定で開けた）

## 本番反映（2026-11-13 13:50 頃）

- 反映前に新しい条件の Prisma クエリを SSH トンネル経由で本番DBに読み取りで実行 → データロー9件（付け忘れ8）・VLL 2件。組織をまたいだ混入なし
- コミットから切った一時 worktree でローカル `docker build` → `misekin-app:corrscope-20261113` → `docker save | gzip | ssh docker load`（24秒）→ `latest` に付け替え → `docker compose up -d --no-build --no-deps app`。サーバー上ではビルドしていない。スキーマ変更なし
- 外形: `/login` 200 / `/correction-requests`・`/dashboard` 未ログインで 307 / `/api/v1/attendance` キーなし 401
- 戻すとき: `docker tag misekin-app:multiclock-20261027 misekin-app:latest` → `docker compose up -d --no-build --no-deps app`
