# 退勤後の再出勤（同じ営業日に勤怠を複数件）

**決定日**: 2026-10-27 ／ **判断**: 高野（推奨案を選択）／ **ブランチ**: `feature/multi-clock-in`（未コミット・本番未反映）

## なぜ

VLLでは、店舗のシフトを退勤したあと、在宅で遠隔推し活にもう一度出勤する。
1人1店舗1営業日に勤怠1件の制約があったので、2回目の出勤が押せなかった（翡翠・2026-10-19）。
休憩扱いはVLLの働き方に合わない、で 10/20 VLL会議で「1日2回出勤できるようにする」と決めた。

## 方針（要件レビューで決めたこと）

- **店舗設定 `Store.allowMultipleClockIns` でオンにした店舗だけ**再出勤できる。既定はオフで、星狼・stagegate は従来どおり
- 退勤済みの人が出勤を押すと、同じ営業日の2件目の勤怠を作る。打刻画面で「本日N回目の出勤です」の確認を挟む
- 同じ日の勤怠どうしは時間帯が重ならないこと（手入力・付け忘れ申請・承認・修正で検証）
- 交通費は「その日に来たか」なので、その日の最初の勤怠にだけ付ける（勤怠API・CSV）
- 店長による打刻修正は既存の手入力・修正（OWNER/ADMIN・担当店舗のみ）で足りる。しのが ADMIN かは本番で未確認

## 何を変えたか

- DB: `attendances` の一意制約 `(staffId, storeId, businessDate)` を外し、通常のインデックスに。
  代わりに部分インデックス `attendances_one_open_per_day`（`clockOutAt IS NULL` の勤怠は1件まで）で二度押しを防ぐ。
  `stores.allowMultipleClockIns` を追加。`schema.sql` / `migrations.sql`（冪等）/ `schema.prisma`
- `lib/business/same-day-attendance.ts`（新規）: 重なり判定・その日の最初の勤怠・打刻の対象の1件の選び方
- `lib/business/time-clock.ts`: `getAvailableActions` / `validateClockTransition` に `allowMultipleClockIns`。
  `calculateDayClockState` を追加し、状態を「勤怠の出勤・退勤」から先に決める
  （イベントの無い手入力の勤怠が「未出勤」に見えて、もう一度出勤できてしまうのを防ぐ。オフの店舗でも効く変更）
- `actions/attendance.ts`: 打刻・手入力・付け忘れ申請・承認・修正を `findSameDayConflict` に寄せた
- 打刻画面: 退勤後の再出勤ボタンと確認ダイアログ。店舗編集にチェックボックス
- 勤怠API・CSV: 交通費をその日の最初の勤怠だけに

## 確認

- 単体 203件（新規 `tests/unit/same-day-attendance.test.ts` を含む）
- 実DB統合 9件（新規 `tests/integration/multi-clock-in.db.test.ts`）: オフの店舗は従来どおり弾く / オンなら2件目 / 二度押しの同時送信で開いている勤怠は1件・エラーは「すでに出勤済みです」/ 手入力の重なり
- 移行: 旧 `schema.sql`＋旧 `migrations.sql` のDBに新 `migrations.sql` を流し、一意制約が消えて部分インデックスができること・2回流しても無エラーを確認。新 `schema.sql` だけの新規DBも通る
- `next build` が通る。ローカルで起動し、退勤済みのスタッフの打刻画面の HTML を見た: オフ=出勤ボタン0・「本日の打刻は完了しています」/ オン=出勤ボタン1

## 気になっていること（未対応）

- 管理画面のダッシュボードの「勤務中・退勤済み」の人数は勤怠の件数で数えている。2件目がある人は2回数えられる（VLLだけ・表示のみ）
- `updateStore` は入力を zod で検証せずにそのまま `update` している（既存）。今回のチェックボックスも同じ経路

## デプロイの注意

- **一意制約は、同じ日に2件目が入った時点で元に戻せなくなる。** 反映前に本番DBのバックアップを `/home/ubuntu/backups/misekin/` に取る（`/opt/apps/misekin/` の中は rsync --delete で消える）
- `deploy.sh` はサーバー上で `docker compose build` する。メモリ2GBの本番でビルドしない方針（`~/.claude/CLAUDE.md`）なので、ローカルでイメージを作って `docker save | ssh docker load` で送る
- 反映後、VLLの店舗編集で「同じ日に退勤後もう一度出勤できるようにする」をオンにする
