# 打刻漏れなど勤怠の異常を本人にメールで知らせる

**日付**: 2026-11-27 ／ **依頼**: 高野「打刻漏れを本人にメールで知らせる機能は作ろう。10月までのやつは知らせなくて良い」 ／ **ブランチ**: `feature/anomaly-mail`（origin/main 起点。本番未反映）

## きっかけ

スタッフに異常を知らせる手段は、ダッシュボードの「対応が必要です」（今月の `hasAnomaly`）だけだった。メールも `notifications` も作られていなかった。
さらに、`hasAnomaly` は退勤・修正のときにしか計算されないので、**退勤漏れの勤怠は `hasAnomaly=false` のまま残り、ダッシュボードにも出ていなかった**。

## 決めたこと

- 毎朝1回、ホストの crontab から `POST /api/cron/anomaly-alerts`（`CRON_SECRET` の Bearer）を叩く。リポジトリに cron が無かったので外部から叩く形にした
- 対象は営業日 2026-11-01 以降・前日まで。実行時に異常を判定し直す。営業日が終わって退勤が無ければ24時間未満でも退勤漏れとする
- 長時間勤務（12時間以上）は「時刻が正しければ対応不要」と添えて1回だけ。退勤漏れ・休憩終了漏れ・退勤<出勤は、7日たっても未対応なら1回だけ再送（最大2回）
- 申請（審査中・承認・却下）・管理者修正・締め済みの勤怠は送らない。送り先は ACTIVE かつ組織メンバー有効なスタッフのログイン用メール
- 送った記録は `attendance_anomaly_notices`（1勤怠1行）。メールが送れなかった分は記録せず翌朝再試行
- 管理者向けの店舗別一覧は案だけ docs に書いた（未実装）

## 残したこと

- ダッシュボードの「対応が必要です」は保存済みの `hasAnomaly` を見たままなので、退勤漏れは出ない。直すなら同じ判定（`evaluateAttendanceForAlert`）を使う
- 本番は `feature/daily-report`（main 未マージ）の版で動いている。反映時はそれとマージする必要があり、`prisma/migrations.sql` と `src/generated/prisma/internal/class.ts` が衝突する（前回 2026-11-25 と同じ型。両方残して `prisma generate`）
